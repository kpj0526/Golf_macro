# 작업 역할 분리 규칙

이 프로젝트는 아래 역할을 섞지 않는다.

## Manager (Codex)

- 요구사항을 짧고 정확하게 Code에 전달한다.
- Code의 커밋을 QA에 전달하고, QA 결과만 사용자에게 보고한다.
- 직접 소스 코드를 수정하거나 테스트를 실행하지 않는다.
- QA 통과 전에는 고객용 빌드, GitHub 배포, 고객 전달을 진행하지 않는다.

## Code (Claude `code` 워크트리)

- 요구사항에 필요한 소스 코드만 수정한다.
- 구현이 끝나면 **커밋하지 않은 상태**로 Manager에게 준비 완료를 알린다.
- QA의 PASS 결과를 받은 뒤에만 `code` 워크트리에서 독립 커밋한다.
- 테스트, UI 실행, 브라우저 실행, QA 문서 갱신, 고객용 빌드/배포/push는 하지 않는다.
- 완료 보고에는 커밋 해시와 변경 파일만 적는다.

## QA (`qa` 워크트리)

- Code가 커밋 전 준비 완료를 알린 뒤, 그 `code` 작업본을 검증한다.
- Code를 수정하지 않는다. 결함은 재현 절차와 로그로 Code에 반려한다.
- 자동 테스트, WinForms UI 확인, 필요한 숨김 브라우저 검증을 모두 수행한다.
- 실제 고객 예약 제출은 절대 하지 않는다.
- PASS/FAIL, 실행한 검증, 증거 경로, 발견 결함을 명확히 보고한다.

## 이번 변경의 정확한 범위

1. 예약 1과 예약 2의 종료 시간 입력칸, 저장값, 검증, 로그를 제거한다.
2. 시작 시간 하나를 희망 티타임으로 유지한다.
3. 선택한 스타터의 모든 예약 가능 티타임 중 희망 시간과 절대 차가 가장 작은 티타임을 고른다.
4. 같은 차이면 더 이른 시간, 그래도 같으면 목록 순서를 사용한다.
5. 과거 5필드 설정은 기존 시작 시간만 읽어 호환한다.

## 작업 순서

`사용자 요구 → Manager 전달 → Code 구현(커밋 전) → QA 전체 검증 → PASS → Code 커밋 → Manager 보고 → 사용자 승인 후 배포`

QA가 FAIL이면 `QA 결함 보고 → Code 수정(커밋 전) → QA 재검증` 순서로만 반복한다.
